# Specialist parity review

Issue #18. Independent review of the working tree on October 28, 2026. Engine/application files were not edited. Sources: [current specialist reference](https://subterfuge-game.com/rulebook/Specialists.html) and [rulebook](https://subterfuge-game.com/rulebook/). The current reference takes precedence over older descriptions.

## Confirmed findings

1. **Medium: Inspector bypasses Revered Elder suppression.** `src/game/specialist-combat.ts`, `resolveStationArrival`, final Inspector refill (line 86), ignores `phase.suppressed`. The [Elder reference](https://subterfuge-game.com/rulebook/Specialists.html) excludes other specialists from combat when only one side has an Elder. Reproduce through public interfaces: `createGame(0)`; add a defending Inspector owned by `vesper` to `f`, set its shield to zero; add an Elder owned by `you` to `c`; `dispatch(game, 'c', 'f', 1, 'you', false, [elderId])`; advance to that fleet's arrival with rivals disabled. The defender survives and its shields become 10/10 despite suppression. Gate the combat refill using the phase result; preserve the separate friendly-arrival refill.

2. **Medium: Intelligence Officer's distant-type benefit is granted to everyone.** `src/game/visibility.ts`, `observe`, hidden-rock projection (line 32); also returned by `server/service.ts`, `view`. The [reference](https://subterfuge-game.com/rulebook/Specialists.html) gives distant outpost-type revelation to Intelligence Officer; the [visibility rules](https://subterfuge-game.com/rulebook/) otherwise reveal distant mines and chart locations. Reproduce: `observe(createGame(0), 'you').rocks.filter(r => !r.known)` already contains exact factory/generator types, including `e: factory` and `j: generator`, with no Intelligence Officer. Redact non-mine distant types unless the observer has an active Intelligence Officer. This is an existing visibility contract gap exposed by the specialist feature, not necessarily newly introduced code.

3. **Medium: Incoming enemy subs are hidden outside sonar, including their specialists.** `src/game/visibility.ts`, `observe`, `contacts` filter (line 24). The [visibility rules](https://subterfuge-game.com/rulebook/) make subs heading for your outposts or subs visible independently of sonar. Reproduce: `g = advance(dispatch(createGame(0), 'f', 'c', 1, 'vesper'), 0.2, { rivals: false })`; authoritative fleets length is 1, but `observe(g, 'you').fleets.length` is 0 although `c` is yours. Include incoming destinations and interception targets in contact eligibility. This also predates the specialist-specific logic and affects public server snapshots.

## Interpretation questions, not confirmed defects

- **Saboteur ends the whole encounter.** `src/game/combat-abilities.ts`, `applyCombatAbilities`, lines 20-24, returns before Thief, Assassin, and driller phases. Existing encounter test demonstrates unchanged 20/30 manifests against Thief. The [reference](https://subterfuge-game.com/rulebook/Specialists.html) specifies redirection but, unlike Infiltrator/Double Agent, does not explicitly say combat ends. Confirm whether immediate separation intentionally prevents all later phases before changing it.
- **Saboteur permanently prevents Navigator course changes.** `returnHauler(..., true)` sets `courseLocked`; `changeCourse` rejects it forever. The [Navigator/Saboteur entries](https://subterfuge-game.com/rulebook/Specialists.html) don't specify that restriction. Confirm intended precedence; a redirected Navigator can otherwise meet the ordinary eight-hour requirement.
- **Promotion requires a docked Queen.** `src/game/specialists.ts`, `promoteSpecialist` calls `requireRecruitment`, requiring `status.at`. The [rulebook](https://subterfuge-game.com/rulebook/) explicitly requires a docked Queen for hiring and a docked specialist for promotion, but doesn't clearly extend the Queen restriction to promotion. Confirm before relaxing it.

## Verification and limits

- Ran `node --import tsx --test src/game/specialist*.test.ts server/specialists.test.ts`: 30 passed, zero failed. This includes exact-boundary versus partial polling for Sentry/Tinkerer/Tycoon, scoped server identities/retry/restart, capture/succession, unit-only return convoys, simultaneous Assassins, area destruction, Pirate interception, Navigator cooldowns, recruitment, and save validation.
- Ran bounded public-interface experiments for all three confirmed findings. Friendly arrival with Queen plus Inspector correctly filled the refreshed shield maximum (30/30); no finding there.
- Read the requested simulation, specialist, combat, destruction, encounter, orders, visibility, save, and service contracts; inspected selected tests. No full interaction matrix, arbitrary polling fuzzing, exhaustive simultaneous multi-fleet destruction, recruitment distribution proof, or independent server concurrency audit. Passing tests establish their scenarios, not complete rule parity. Recruitment offer-deck details aren't specified by these two official pages and weren't treated as proven deviations.
